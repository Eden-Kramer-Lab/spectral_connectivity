## Overview

`spectral_connectivity` is a Python package for computing multitaper spectral estimates and frequency-domain brain connectivity measures. It provides tools for functional and directed connectivity analysis of electrophysiological data, with optional GPU acceleration via CuPy.

## Core Architecture

The package follows a modular design with three main components:

1. **Transforms** (`src/spectral_connectivity/transforms.py`): Implements the `Multitaper` class for computing multitaper Fourier transforms
2. **Connectivity** (`src/spectral_connectivity/connectivity.py`): The `Connectivity` class computes various connectivity measures from spectral estimates
3. **Wrapper** (`src/spectral_connectivity/wrapper.py`): Provides `multitaper_connectivity()` function as a high-level interface

### Key Design Patterns

- **GPU/CPU Abstraction**: Uses `xp` namespace (numpy or cupy) controlled by `SPECTRAL_CONNECTIVITY_ENABLE_GPU` environment variable
- **Caching**: Frequently computed quantities like cross-spectral matrices are cached for performance
- **Expectation Framework**: Uses the `EXPECTATION_AXES` dictionary to handle averaging over different dimensions (time, trials, tapers)

### Main Classes

- `Multitaper`: Handles multitaper spectral estimation
- `Connectivity`: Computes connectivity measures from spectral data
- Both classes support method chaining and lazy evaluation patterns

## Development Commands

### Environment Setup
```bash
# uv (recommended): .venv from uv.lock with the package editable plus the dev tools
uv sync
uv run pytest            # prefix any command with `uv run` to use that environment
uv lock                  # after changing dependencies in pyproject.toml
uvx pre-commit install   # once; each commit then runs ruff, codespell, mypy and the file checks

# Or conda
conda env create -f environment.yml
conda activate spectral_connectivity
pip install -e .[dev]
```

### Testing
```bash
# Run all tests (pyproject.toml adds coverage of src/spectral_connectivity)
uv run pytest

# Run specific test file
uv run pytest tests/test_connectivity.py -v

# Run single test
uv run pytest tests/test_connectivity.py::test_power_one_sided_preserves_total_power -v
```

### Code Quality
```bash
# Format code (examples/ holds Jupytext tutorials and is excluded from ruff)
uv run ruff format src/ tests/

# Check formatting (what CI runs)
uv run ruff format --check src/ tests/

# Lint code (what CI runs)
uv run ruff check src/ tests/

# Fix auto-fixable linting issues
uv run ruff check --fix src/ tests/

# Type checking
uv run mypy src/
```

### Building and Release
```bash
# Build sdist and wheel into dist/ (hatchling + hatch-vcs; hatch itself is not installed)
uv build

# Clean build artifacts
rm -rf build/ dist/ *.egg-info/
```

## Important Configuration

### GPU Support
Set environment variable `SPECTRAL_CONNECTIVITY_ENABLE_GPU=true` to enable GPU acceleration via CuPy.

### Dependencies
- Core: numpy, scipy, xarray, matplotlib
- Dev tools (the `dev` extra and `dev` dependency group in `pyproject.toml`; keep
  the two lists identical): pytest, pytest-cov, syrupy, nitime, ruff, mypy,
  scipy-stubs, numpydoc, netCDF4, h5netcdf, h5py
- Optional GPU: cupy-cuda12x

## Testing Strategy

- Unit tests in `tests/` directory mirror the source structure
- CI (`.github/workflows/release.yml`) runs the quality gate (ruff format check,
  ruff check, mypy, and the docstring examples via
  `uv run pytest --doctest-modules src/spectral_connectivity/`), a `lockfile`
  job (`uv lock --check`), a test matrix on Python 3.10–3.14 across Ubuntu,
  macOS, and Windows, and a `test-min-deps` job that installs the exact
  dependency floors on Python 3.10, followed by build/install checks and (on
  tag) trusted PyPI publish
- Coverage reporting via Codecov (Linux, Python 3.12)
- Notebook integration tests execute tutorial examples
- Documentation is tested: `docs/CONNECTIVITY_METRIC_RANGES.md` is generated by
  `docs/generate_measure_table.py` and `tests/test_docs.py` fails when it is
  stale; `docs/cookbook.md` and `docs/llm_guide.md` are doctested by
  `tests/test_cookbook.py`
- Tests include both CPU and GPU code paths when available (GPU paths run only
  where CuPy is installed)

## File Structure

```
src/spectral_connectivity/
├── __init__.py              # Main API exports
├── connectivity.py          # Connectivity measures
├── transforms.py           # Multitaper transforms
├── wrapper.py              # High-level interface
├── _measure_registry.py    # One record per wrapper measure (contract + labels); list_measures data
├── _input_handling.py      # Wrapper input validation and xarray DataArray unwrapping
├── _frequency_bands.py     # Frequency selection and band reduction
├── _result_formatting.py   # Per-measure xarray result formatting
├── _provenance.py          # Result provenance attributes and serialization
├── minimum_phase_decomposition.py
├── statistics.py           # Statistical utilities
├── simulate.py             # Data simulation utilities
├── utils.py                # GPU backend selection, array helpers
├── py.typed                # PEP 561 marker: the package ships type hints
└── _version.py             # Generated by hatch-vcs at build time; gitignored
```
