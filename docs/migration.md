# Migrating from 2.x to 3.0

spectral_connectivity 3.0 corrects several numerical definitions, so it is a
major version. Recompute affected results rather than comparing them directly
with results from 2.x. The [changelog](https://github.com/Eden-Kramer-Lab/spectral_connectivity/blob/master/CHANGELOG.md)
lists everything that was added and fixed; this page lists what code written
for 2.x has to change.

## If you only change five things

1. **Swap the indices of directed results.** The `Connectivity` methods of the
   spectral Granger family, `directed_transfer_function`, `directed_coherence`,
   `partial_directed_coherence`, `generalized_partial_directed_coherence`, and
   `direct_directed_transfer_function` return `[..., source, target]`:
   `result[..., i, j]` is now `i -> j`, where 2.x returned `j -> i`. In the
   wrapper results, `multitaper_connectivity(...).sel(source="a",
   target="b")` of pairwise and subset spectral Granger prediction is now
   `a -> b`, where 2.x returned `b -> a`. Code written for 2.x still runs but
   reads the opposite direction, so swap its indices and recompute stored
   results. `phase_slope_index`, `group_delay`, and `delay` were already
   source first: do not swap them. Until 3.2 the `Connectivity` methods that
   existed in 2.x, and `multitaper_connectivity` and `connectivity_to_xarray`
   for pairwise and subset spectral Granger prediction, emit a
   `DirectedOrientationWarning` as a reminder; silence it with
   `warnings.filterwarnings("ignore",
   category=spectral_connectivity.DirectedOrientationWarning)`.
2. **Expect one-sided power.** `Connectivity.power()` returns the one-sided
   density: the bins between 0 Hz and Nyquist are twice the 2.x values.
   `power(one_sided=False)` returns the 2.x values. Until 3.2, calling
   `Connectivity.power()` without `one_sided` on two-sided coefficients emits a
   `PowerSidednessWarning`; pass `one_sided=True` to silence it. The power in
   `multitaper_connectivity` and `connectivity_to_xarray` results changed the
   same way without a warning: halve its interior bins to compare with 2.x.
3. **Read `magnitude_squared_coherence`, not `coherence_magnitude`.** The
   default `multitaper_connectivity` Dataset has no `coherence_magnitude`
   variable, so indexing it by the old name raises `KeyError` or
   `AttributeError`. Requesting `method="coherence_magnitude"` or calling
   `Connectivity.coherence_magnitude()` still works through 3.x, with a
   `DeprecationWarning`.
4. **Replace the deprecated spellings.** Use `Connectivity.from_transform(m)`
   instead of `Connectivity.from_multitaper(m)`, and
   `frequency_range=(low, high)` instead of `frequencies_of_interest` for
   `phase_slope_index`, `group_delay`, and `delay`. `frequency_range` includes
   both endpoints, where `frequencies_of_interest` excluded a bin on either
   edge. The old spellings still work through 3.x with a `DeprecationWarning`
   and are removed in 4.0.
5. **Pass `sampling_frequency` to `Multitaper`.** 2.x defaulted it to 1000 Hz;
   it is now required, and leaving it out raises `TypeError`.

The tables below list every change, including the measures whose values were
corrected.

## Changes to interfaces that existed only in development builds

These rows concern code written against the development branch after 2.0.1:
those interfaces were renamed before their first release, with no
compatibility path. Most old spellings fail loudly or are absent; two do not:
a positional call to `simulate_lagged_broadband` still runs but now returns a
trial axis, and the `backend` attribute is still present but lowercase, so a
comparison with `"CPU"` or `"GPU"` is silently false (see their rows).

| Previous behavior | New behavior / required action |
| --- | --- |
| `frequency_band_reduce(result, bands=..., reduction=...)` | `frequency_band_reduce(result, frequency_bands, frequency_reduction=...)`, the wrappers' names; the band mapping stays the second positional argument and `frequency_reduction`/`circular` are keyword-only. The old keywords raise `TypeError` |
| Component results' `connection_seed_group` coordinate and `side=["seed", "target"]` | `connection_source_group` and `side=["source", "target"]`, the source/target vocabulary of every labeled result: `.sel(side="seed")` raises `KeyError` |
| Transform-prefixed result attributes (`stft_*`, `welch_*`, `morlet_*`, `fourier_*`), `mt_*` copies of settings 2.0.1 never recorded (`mt_fft_workers`, `mt_taper_weighting`, `mt_adaptive_tolerance`, `mt_adaptive_max_iterations`), and `backend="CPU"`/`"GPU"` | The shared keys of the result schema (`transform`, `sampling_frequency`, `n_observations`, ...), settings in `transform_parameters_json` (`fft_workers` under `execution`), and lowercase `backend="cpu"`/`"gpu"`. `fourier_source` became `transform="external_fourier"`, and `stft_n_tapers` (always 1) has no replacement |
| `frequency_band_lower`/`frequency_band_upper` and `frequency_range_json` on interval results | `selected_frequency_lower`/`_upper` and `frequency_interval_closed` on every interval result and every variable a `frequency_range` applied to, plus `requested_frequency_lower`/`_upper` when a band was requested (a `phase_slope_index` result computed over every bin has none); `measure_kwargs_json` and `arg_*` still record the keyword as given |
| `ShortTimeFourierTransform(...).frequency_resolution` (Hann equivalent noise bandwidth) | `equivalent_noise_bandwidth`, also on `Welch`; only `Multitaper` has `frequency_resolution`, its DPSS concentration bandwidth |
| Settings of the new APIs passed by position: `ShortTimeFourierTransform`, `Welch`, and `MorletWavelet` after `sampling_frequency`; `fourier_connectivity` after `signal_names`; `rank` and `regularization`; `global_coherence`'s `max_workspace_elements` | Pass them by keyword; a positional value raises `TypeError` instead of binding to the wrong setting. Released positional orders (`Multitaper`, `multitaper_connectivity`, `connectivity_to_xarray`, `global_coherence(max_rank)`, `minimum_phase_decomposition`) are unchanged |
| `simulate_lagged_broadband(lags=..., ...)`, which returned `(time, signal)` unless `n_trials` was given | `lags_samples=...` (whole samples; for a delay in seconds pass `round(delay * sampling_frequency)`, which sends an exact half to the even neighbour and makes a delay of half a sample or less 0). It returns `(time, trial, signal)` with `n_trials=1` by default, like `simulate_MVAR`; pass `n_trials=None` for `(time, signal)`. `lags=` raises `TypeError`, but a positional call such as `simulate_lagged_broadband((0, 3), 0.1, 100)` runs and returns `(100, 1, 2)` instead of `(100, 2)`, so `x[:, 0]` now selects every signal of trial 0 rather than signal 0: index `x[:, 0, k]` or pass `n_trials=None` |
| `simulate_shared_oscillation(frequency, sampling_frequency, n_time_samples, n_trials, amplitudes)` | `amplitudes` is a required keyword (`amplitudes=[...]`) and `n_trials` defaults to 1; passing the amplitudes fifth raises `TypeError`. `frequency` and `sampling_frequency` are in Hz |
